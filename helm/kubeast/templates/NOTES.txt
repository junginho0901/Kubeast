Follow these steps. Each command is one line and works the same
in bash, zsh and PowerShell.

[1] Wait until the pods are up (usually 1 to 5 minutes)

    kubectl -n {{ $ns }} wait --for=condition=Available deployment --all --timeout=5m

    Each Deployment prints "condition met" when it is ready.
    kubectl -n {{ $ns }} get pods shows the progress.

[2] Open the gateway in a browser
{{- if .Values.ingress.enabled }}

    {{ if .Values.ingress.tls }}https{{ else }}http{{ end }}://{{ .Values.ingress.host }}
{{- else if eq .Values.gateway.service.type "NodePort" }}

    Docker Desktop    http://localhost:{{ .Values.gateway.service.nodePort }}
    Other clusters    http://<node-ip>:{{ .Values.gateway.service.nodePort }}
                      node-ip: INTERNAL-IP in kubectl get nodes -o wide
{{- else if eq .Values.gateway.service.type "LoadBalancer" }}

    http://<EXTERNAL-IP>:8000
    EXTERNAL-IP: kubectl -n {{ $ns }} get svc gateway (it can take a minute or two)
{{- end }}

    If the address does not open, keep this running and open http://localhost:8000:
    kubectl -n {{ $ns }} port-forward svc/gateway 8000:8000
{{- if and .Values.auth.cookieSecure (not .Values.ingress.tls) }}

    ⚠ Over plain http:// on an address other than localhost, the browser drops
      the sign-in cookie and sign-in fails. Upgrade with
      --reset-then-reuse-values --set auth.cookieSecure=false in that case.
{{- end }}

[3] Sign in as admin

    ID         {{ .Values.admin.email }}
{{- if .Values.admin.password }}
    Password   the admin.password set at install
{{- else }}
    Password   generated at install; this prints it:

    kubectl -n {{ $ns }} get secret {{ include "kubeast.secretsName" . }} -o go-template='{{ "{{" }}.data.DEFAULT_ADMIN_PASSWORD | base64decode | println{{ "}}" }}'
{{- end }}

[4] Change the admin password right after signing in

[5] Connect a cluster to manage
    With no cluster registered, the setup page (/setup) opens after sign-in.
{{- if .Values.ai.enabled }}

[6] Turn on the AI chat (optional)
    Register an OpenAI, Anthropic, Gemini … key on Admin > AI Models.
{{- else }}

[6] AI is off (ai.enabled: false)
    Installed without ai-service, tool-server and the ModelConfig controller.
    To turn it on, upgrade with --reset-then-reuse-values --set ai.enabled=true.
{{- end }}

▸ Upgrading

    helm upgrade {{ .Release.Name }} oci://ghcr.io/junginho0901/charts/kubeast --version <version> -n {{ $ns }} --reset-then-reuse-values

    --reuse-values keeps this version's defaults and stops on values a later version added.
