Each "what stops it" cell says where the control lives:

- **main**: in `main` at the v0.7.9 tag. **main, unchanged** adds that this release leaves the file as it is.
- **branch** (commit): in a commit of this release, read at that commit before its pull request merged. When it merges, the cell says **merged in #n**.
- **decided** (who, date): a decision with no code yet.
- **none**: nothing in Kubeast's code stops it.

The "left before release" cell names the step that owns the item: the pull request's CI, the release QA (every screen in the three colour modes, the keyboard flows, one pass with a screen reader), or the release gate (the full e2e, the runs of 500 people, the upgrade rehearsal from 0.7.9 and back). What has not been run or confirmed is written **Not yet**, with what to run. A cell closed without a fix ends with **Not in this release** (who, date): why it waits. **Decision** marks a choice for the maintainers; **Unconfirmed** marks something read but not checked.

A gap in released code is described by what is missing and how it is fixed, not by how to use it. Report a security problem privately, as [SECURITY.md](../../SECURITY.md) says.

## 1. What are we working on?

### Data flow

The screens (change 1 below):

```
 Who writes the text                          Where it waits                   How the page draws it
 ───────────────────                          ──────────────                   ─────────────────────
 a model: chat answers, reports,      ──────► session-service, ai-service ──►  Markdown: chat answers (HTML read, then
 optimization answers; shaped by                                               filtered); report and optimization answer
 what it read (logs, events, alerts)                                           (HTML shown as words)
 anyone who can write a cluster object ─────► the managed cluster ── k8s-service ──► React text: lists, drawers, events,
 or make a pod print                                                           describe, logs; Monaco (YAML); xterm (terminals)
 a Helm release's author ───────────────────► the release's Secret ── k8s-service ──► an HTML string: diff2html

════════════════════════════════════════════════════════════════════════════ TB7 text written outside the page → elements of the page

```

```
   ▼

 every cluster's reads of k8s-service ── places of one k8s-service: the pod rows, the pod lists as the person, the big reads
                                         (each cluster at most half of the last two while more than one is registered)
```

The AI (changes 4 to 6 below):

```
 AI Chat · floating chat · MCP · alert investigations (ai-service)
   │  instructions + tool results; no stored report reaches an investigation
═══╪═══════════════════════════════════════════════════════ TB6 ai-service ⇄ the model provider
   ▼

   │  tool calls
   ▼

═══╪═══════════════════════════════════════════════════════ TB5 Kubeast → the managed clusters
   ▼
 API servers · Prometheus (busiest CPU, the caller's p90) · Tempo (span table)
```

The rows use the trust boundaries TB1 to TB6 of the [v0.7.8](v0.7.8.md) and [v0.7.9](v0.7.9.md) pages: outside → Kubeast's namespace, Kubeast → the managed clusters (TB5) and ai-service ⇄ the model provider (TB6) among them. This page adds **TB7**: text written outside the page becomes elements of a page that holds the viewer's session, so whatever runs there acts with the viewer's rights in Kubeast and, through Kubeast, in the clusters; text from a model, a cluster, an alert or a Helm release is not trusted, whoever wrote it, and chart values and admin settings, written by people who already hold more than the viewer, are drawn with the same care but rated lower.

### What is worth protecting here

- The viewer's session and rights: whatever runs in the console's page sends requests as the viewer.
- What the page says: a console that shows a link, a command, a log line or an object must show what is there, not what a writer made it look like, and not another object's.
- The approval card of an AI write: it must show what will run.
- What a grant limited to namespaces may read, and what one person's answer holds: no other person's answer, and no stream outside what the person may read.
- The audit rows, which say what the console and the AI did, and the masking of the values in them.
- The clusters' API servers and the stores Kubeast reads, and k8s-service's memory, which many people share.

## 2. What can go wrong, and 3. what are we doing about it

STRIDE letters: **S** spoofing, **T** tampering, **R** repudiation, **I** information disclosure, **D** denial of service, **E** elevation (acting with rights one was not given). Each threat cell says what is drawn or read and who writes it. Paths starting `components/`, `pages/`, `utils/`, `hooks/` or `i18n/` are under `frontend/src/`; paths starting `internal/` are under the service the row names; `nginx.conf` is `helm/kubeast/files/nginx.conf`; other paths are from the repository root.
